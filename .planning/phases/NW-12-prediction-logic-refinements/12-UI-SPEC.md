## Visual Hierarchy

**Today screen focal point:** The `.next-event-hero` card is the primary visual anchor. It occupies the full card width at the top of the scroll area, uses the accent background (`#4f46e5`), and carries the largest text (Display 36px). All other elements are subordinate.

**Eye sequence:** `.next-event-hero` hero card → 4-card prediction grid (`napStart`, `napEnd`, `bedtime`, `wake` in that order after UI-07 fix) → bottom navigation bar.

**Phase 12 additions inherit this hierarchy:** The nap probability line sits inside the hero card (when nap-start is next) or inside a prediction grid card — both positions are already below the hero in the visual stack. The intense-day badge sits in the history table, which is on a separate screen; it does not affect Today-screen hierarchy.

## Component Inventory

### 1. Nap Probability Line (PRED-12)

**Where:** `.prediction-card` (nap-start card in 4-card forecast grid) AND `.next-event-hero` when nap-start is the next event.

**CSS class:** `.nap-probability`

**Markup:** `<p class="nap-probability">73% chance of nap today</p>` — rendered with `textContent`, never `innerHTML`. Placed after `.time-band` inside the card.

**States:**

| State | Copy | Style |
|-------|------|-------|
| Active window, score > 0 | "{N}% chance of nap today" | `color: #475569; font-size: 0.875rem; font-weight: 400; margin: 0; margin-top: 0.25rem;` |
| Window passed (nap-start P90 exceeded) | "0% — nap window closed" | Same style; score collapses to 0 per D-13 signal 4 |
| Nap already logged (missed/past state) | Element suppressed | Do not render `.nap-probability` when card has `.missed` class |
| Insufficient data (< minDays) | Element suppressed | Do not render when score cannot be computed |

**Discretion resolution (from CONTEXT.md §Claude's Discretion):**
When the nap window has passed, use option (a): hard 0% with "nap window closed" copy. Suppressing the element entirely would produce inconsistent card height and omit useful information. The "0% — nap window closed" copy is informative and non-alarming.

**Hero card variant:** On `.next-event-hero` when nap-start is next event, add:
```
.next-event-hero .nap-probability {
  font-size: 0.875rem;
  font-weight: 400;
  opacity: 0.85;
  color: #fff;  /* hero card is indigo-background */
  margin: 0;
  margin-top: 0.125rem;
}
```

### 2. Intense-Day Checkbox (PRED-10, D-04)

**Where:** `#manualEntry` form — new row below the event-type select, visible for all event types.

**CSS class:** `.checkboxRow` (reuses existing `#settings label.checkboxRow` pattern)

**Markup:**
```html
<label class="checkboxRow">
  <input type="checkbox" id="intenseDay" name="intenseDay" />
  Intense day
</label>
```

**Style:** Inherits existing `#manualEntry label` rules — `flex-direction: row; align-items: center; gap: 0.5rem; font-size: 0.9rem; color: #334155;`. Checkbox `accent-color: #4f46e5` (matches rejected-toggle).

**Pre-checked:** When editing an event for a date already in `settings.intenseDays`, the checkbox is pre-checked. State is derived from `settings.intenseDays` includes the event's calendar date.

**Persist:** On form submit, adds or removes the date from `intenseDays` in the settings store. No new confirm step — same instant-persist pattern as rejected-toggle.

### 3. Intense-Day Badge (PRED-10, D-05)

**Where:** History table, per-day row — rendered as an interactive button badge alongside the date or in the actions column.

**CSS class:** `.intenseBadge`

**Markup:** `<button class="intenseBadge" type="button" data-date="{YYYY-MM-DD}" title="Intense day — click to remove">Intense</button>`

**Style:**
```css
.intenseBadge {
  display: inline-flex;
  align-items: center;
  padding: 0.15rem 0.5rem;
  background: #eef2ff;
  color: #4338ca;
  border: 1px solid #c7d2fe;
  border-radius: 9999px;
  font-size: 0.875rem;
  font-weight: 400;
  cursor: pointer;
  min-height: 28px;       /* visual minimum; 44px touch target via wrapper row */
  line-height: 1;
  vertical-align: middle;
}

.intenseBadge:hover {
  background: #e0e7ff;
  border-color: #a5b4fc;
}

.intenseBadge:focus-visible {
  outline: 2px solid #4f46e5;
  outline-offset: 2px;
}
```

**Rendering location:** Injected into the day's date cell (`.day-date` td) immediately after the date text, or as a separate element in the same cell. Do not add a new column — the table already has many columns and a new one would break the responsive layout.

**Visibility:** Rendered only when `intense === true` on a day record. Clicking fires `settings.update({ intenseDays: [...intenseDays without this date] })` and removes the badge from the DOM immediately.

**No confirmation dialog:** Instant removal matches the rejected-toggle pattern. The action is reversible via the manual-entry checkbox.

**History table row modifier:** Add `.intense` class to `<tr>` when `intense === true`. No visual styling required beyond the badge (rejected rows use opacity; intense days do not need dimming — they are positive signal days, not outliers).

### 4. Settings: Forecast Section New Inputs (D-06, D-08)

**Where:** `#settings` form, Forecast `<fieldset>` — two new `<label>` entries.

**eveningHour input:**
```html
<label>
  Evening hour (0–23)
  <input type="number" id="eveningHour" name="eveningHour" min="0" max="23" step="1" />
</label>
```

**noNapBedtimeOffsetMinutes input:**
```html
<label>
  No-nap bedtime offset (min)
  <input type="number" id="noNapBedtimeOffsetMinutes" name="noNapBedtimeOffsetMinutes"
         min="0" max="120" step="5" />
</label>
```

Both inputs inherit `#settings input[type="number"]` styles: `min-height: 44px; padding: 0.4rem 0.5rem; font-size: 1rem; border: 1px solid #cbd5e1; border-radius: 0.25rem; width: 100%; background: #fff;`

Validation errors surface via existing `.settingsErrors` element (no new error surface needed).

### 5. Card Order Fix (UI-07)

Pure code change in `js/ui/today-screen.js:516`. No new CSS or HTML elements. Array changes from `['wake', 'bedtime', 'napStart', 'napEnd']` to `['wake', 'napStart', 'napEnd', 'bedtime']`.
