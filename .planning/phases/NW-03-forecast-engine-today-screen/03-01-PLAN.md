<task type="tdd">
  <name>Task 2: GREEN — Implement percentile calculation and core forecast logic</name>
  <files>js/lib/forecast.js</files>
  <behavior>
    - percentile(sorted, p) function implements linear interpolation formula (D3-01, Code Example 1 from RESEARCH):
      - Handle edge cases: empty array (return null), single element, bounds checking
      - Use 1-based position formula: pos = p * (n + 1)
      - Convert to 0-based: k = floor(pos - 1), frac = pos - floor(pos)
      - Interpolate: result = sorted[k] + frac * (sorted[k+1] - sorted[k])
      - Clamp to bounds if position outside array
    - calculatePercentiles(dayRecords, getTimeFn, rejectWeight=0.5) function:
      - Extract times from day records using getTimeFn (e.g., d => d.wake)
      - Convert times to numeric minutes-since-midnight for sorting
      - Sort numerically
      - Compute effective count: sum(d.rejected ? rejectWeight : 1.0)
      - Calculate P10, P50, P90 using percentile() function on sorted numeric array
      - Return { min: P10, central: P50, max: P90 } as numeric minutes
    - selectCentralTime(times) is alias for P50; returns median per D3-05
    - downweightRejectedDays(dayRecords, weight): helper that annotates each record with its effective weight (not mutating input; return new array with weight metadata)
    - forecast(dayRecords, settings) main function:
      - Extract settings: minDays, maxDelta, windowDays, statBlend (locked to 'median' in Phase 3)
      - Slice dayRecords to last windowDays
      - For each event type (wake, bedtime, napStart, napEnd):
        - Filter to days where that event exists
        - Call calculatePercentiles with downweighting
        - Convert numeric minutes back to 'HH:MM' strings (5-minute precision)
        - Return { central, min, max }
      - Return { wake, bedtime, napStart, napEnd } each with { central, min, max }
      - If any event has no days of history, return { central: null, min: null, max: null } (allows upstream to handle cold-start)
