# Phase 11 — UI Design Contract

> Visual and interaction contract for the Metrics Screen — dedicated 5th-tab analytics dashboard showing per-day duration/activity/ratio metrics and historical aggregates.
> Generated by gsd-ui-researcher from upstream CONTEXT.md, RESEARCH.md, and REQUIREMENTS.md decisions.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — vanilla HTML/CSS |
| Icon library | inline SVG in bottom-nav.js |
| Font | system-ui, -apple-system, "Segoe UI", Roboto, sans-serif |

**Rationale:** Project constraint (CLAUDE.md) — zero npm dependencies, no build step, no frameworks. Design system established in Phase 1–8 (calm palette, monospace numbers, sticky tables). Metrics Screen extends existing patterns from accuracy-screen.js and charts-screen.js (stageChip badge, filterDayRecordsByStage, subscribe/unsubscribe mount pattern).

---

## Visual Hierarchy

**Primary focal point:** Metrics table with sticky column headers and first-column anchor

The metrics table is the dominant visual element. Its persistent header (position: sticky; top: 0) and sticky first column (position: sticky; left: 0) establish clear navigation anchors for users scanning both vertically and horizontally. Summary rows (Average/Min/Max) sit above per-day rows in the same scroll container, creating a secondary hierarchy: aggregates first, then historical detail. Rejected days are visually muted (opacity 0.5) to de-emphasize outliers without hiding them. The stage filter badge appears above the table as a tertiary element, indicating active scope without competing for attention.

## Data Formatting

### Durations (Sleep, Nap, Combined, Day Length, Act→Nap, Nap→Bed, Activity columns)

**Format:** `Xh Ym` (e.g., "7h 30m", "0h 45m", "0h 0m")

**Implementation (D11-20, D11-22):**
```js
function formatDuration(minutes) {
  const hours = Math.floor(minutes / 60);
  const mins = minutes % 60;
  return `${hours}h ${mins}m`;
}
```
- Location: new export in `js/lib/time.js` OR local to `js/ui/metrics-screen.js` (Claude's discretion)
- Apply to all duration columns in summary + per-day rows
- Average durations in summary row also formatted this way, rounded to nearest minute

### Ratios (AAS, SAA columns)

**Format:** Two decimal places (e.g., "1.85", "0.42")

**Implementation (D11-21):**
```js
function formatRatio(value) {
  return value === null ? '—' : value.toFixed(2);
}
```
- No unit suffix
- Null values show em-dash ("—")

### Times (Wake, Bedtime, Nap Start, Nap End columns)

**Format:** Respects user's timeFormat setting (12h/24h)

**Implementation (D11-08):**
```js
// Use existing formatTime() from js/lib/time.js
formatTime(eventTime, settings.timeFormat)  // e.g., "07:30" or "7:30 AM"
```

## Mount Pattern

The `mountMetricsScreen({ root, eventLog, settings })` function follows the established pattern from accuracy-screen.js and charts-screen.js:

### Signature
```js
export function mountMetricsScreen({ root, eventLog, settings }) {
  // Returns { unsubscribe() { sub1(); sub2(); } }
}
```

### Key Behaviors
1. **Adapter injection:** No direct `new Date()` or `localStorage` calls; uses injected adapters (eventLog, settings)
2. **Reactive render:** Subscribe to both eventLog and settings; re-render on any mutation
3. **XSS guard:** All dynamic content (stage name, formatted times, durations) set via textContent, never innerHTML (T-07)
4. **Stage filter:** Use `filterDayRecordsByStage(allDays, snap.stages || [], snap.activeStageId)` from day-bucket.js (3-arg form, Research Pitfall 1)
5. **Return value:** `{ unsubscribe() { ... } }` for lifecycle management

### Render Flow
1. Get day records: `eventLog.getAllDayRecords()` (or equivalent getter)
2. Get settings snapshot: `settings.getSnapshot()`
3. Filter by stage: `filterDayRecordsByStage(allDays, snap.stages || [], snap.activeStageId)`
4. Call `aggregateMetrics(filteredDays)` from `js/lib/metrics.js` to compute summary rows
5. Build table DOM:
   - `.stageChip` badge (if stage active)
   - Summary rows (Avg, Min, Max)
   - Per-day rows (most-recent-first)
6. Update root via `replaceChildren()`

## Edge Cases & Backstop Conditions

| Edge Case | Handling | Verification |
|-----------|----------|--------------|
| Day 1 (no previous-day context for SAA) | SAA shows "—"; excluded from SAA aggregates | aggregateMetrics() returns null for day 0's SAA |
| Days with no nap logged | Nap-dependent columns show "—"; excluded from nap aggregates (Nap, Combined, Act→Nap, Nap→Bed, AAS, SAA) | No-nap days identified by `napDuration(day) === null` |
| Rejected day (outlier flag) | Dimmed row (opacity 0.5, faint bg); excluded from all aggregates EXCEPT SAA computation (D11-13, may vary) | `day.rejected === true` check; filtered before aggregate math |
| All days rejected | Summary row hidden (or shown with all "—" values); per-day rows still visible but all dimmed | aggregateMetrics() returns empty/fallback aggregates |
| No days logged | Cold-start note + table hidden (D11-07: no gate, but empty state still rendered) | eventLog.getAllDayRecords().length === 0 |
| Very long stage name | Truncate or wrap in badge (clip-path / text-overflow) | Badge uses inline-flex, text-overflow: ellipsis if needed |
| Horizontal overflow on narrow screens | Table scrolls; sticky header + first col remain fixed (D11-17, D11-18) | CSS position: sticky + z-index layering |
| Vertical scroll (many days) | Sticky header remains at top (D11-18); summary rows scroll with data | position: sticky; top: 0 on `<th>` elements |
