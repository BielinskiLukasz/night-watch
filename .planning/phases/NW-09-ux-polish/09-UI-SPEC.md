## Typography

Font weights are strictly limited to 400 (regular) and 600 (semibold) per Phase 8 D8-13.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 1rem (16px) | 400 | 1.4 | Default text, event labels |
| Label | 0.9rem / 0.875rem (14–15px) | 400 | 1.4 | Form labels, field descriptions |
| Heading | 1.15rem (18px) | 600 | 1.4 | Modal titles, section headings |
| Display | 2.25rem (36px) | 600 | 1.1 | Hero card time display |

**Fine-tuning sizes in scope:**
- Collapsed card label: 0.875rem, weight 400 (matches existing `.event-label`)
- Collapsed card time range: 0.875rem, weight 400
- Chevron: 1rem or Unicode character

## Component Specifications

### 1. Collapsed Probability-Band Forecast Card (UI-09)

**Trigger:** Rendered when `hasProbBand` is true (±delta > max_delta).

**Default state:** Collapsed (compact row).

**Rendered as:**
```
[Event Label] • [Start time]–[End time] ↓
```

Example: `Bedtime • 22:00–23:45 ↓`

**Styling:**
- Container: `.prediction-card` (existing base class) + optional `.collapsed` state class
- Row height: 44px min (tap target compliance)
- Font size: 0.875rem (match existing `.prediction-card .event-label`)
- Font weight: 400 (body text, not label)
- Display: Flex row, align-items center, space-between (label on left, chevron on right)
- Border: 1px solid #e2e8f0 (match existing card border)
- Border radius: 0.375rem (match existing cards)
- Padding: 0.875rem 1rem (match existing cards)
- Chevron character: Unicode ↓ (DOWN ARROWHEAD, U+2B0F) or › (RIGHT-POINTING ANGLE BRACKET, U+203A)
- Chevron color: #64748b (match existing `.time-band` text color)
- Chevron hover color: #4f46e5 (accent, signals interactivity)

**Expanded state (click to toggle):**
- Full `.prediction-card` layout (event-label + time-central + time-band + prob-list or time-central)
- Chevron rotates 180° (pointing up) or changes character to ↑

**Reset behavior (D9-06):**
- On every `renderForecastSection()` re-render (reactive on new log events), collapsed cards reset to collapsed state
- No cross-render state persistence needed — DOM is rebuilt from scratch

**Click handler:**
- Toggle a `.collapsed` class on the card
- Prevent event propagation (child buttons remain clickable)

### 2. Edit History Toggle (UI-07)

**Location:** History toolbar (left side, before Export button).

**States:**

| State | Label | aria-pressed | Visual |
|-------|-------|--------------|--------|
| Hidden (default) | Edit history | false | Border 1px #cbd5e1, transparent background |
| Active | Done editing | true | Border 1px #4f46e5, background #eef2ff, text #4f46e5, font-weight 600 |

**Styling:**
- Padding: 0.3rem 0.75rem (match existing toolbar buttons)
- Font size: 0.85rem
- Border radius: 0.25rem
- Cursor: pointer
- Hover (when hidden): background #f1f5f9, text #1e293b
- Hover (when active): background #ede9fe, text #4f46e5

**Behavior:**
- Clicking toggles `aria-pressed="true/false"` and label text
- When active: all `.rowEdit`, `.rowDel`, `.rejected-toggle` become visible in the `.historyTable`
- When inactive: those controls are hidden (CSS `display: none` or existing `disabled` state)
- Toggle state resets to "hidden" when user navigates away from History tab (implicit: remounting screen resets to default)

**ARIA contract:**
- Use `aria-pressed="true/false"` attribute even though label changes (belt-and-suspenders accessibility)
- Button is always enabled (not `disabled` attribute)

### 5. Save More Button (LOG-11)

**Location:** Manual-entry modal footer menu (`#manualEntry menu`).

**Button order in modal footer:**
```
[Cancel] [Save more] [Save]
```

**Markup:**
```html
<menu>
  <button type="button">Cancel</button>
  <button type="button" id="saveMoreBtn">Save more</button>
  <button type="submit">Save</button>
</menu>
```

**Styling:**
- Padding: 0.45rem 1rem (match existing buttons)
- Font size: 0.95rem, weight 400
- Background: #fff, border 1px solid #cbd5e1, color #475569 (matches Cancel)
- Hover: background #f1f5f9
- Hidden by default; shown only when opened via "+ Add event" button

**Visibility control:**
- Controlled by `openManualEntry()` parameter: `saveMore: true` or `saveMore: false`
- When `saveMore: false`, set `#saveMoreBtn { display: none }`
- When `saveMore: true`, set `#saveMoreBtn { display: block }`

**Behavior:**
1. User fills in form (type, time, date)
2. Clicks "Save more"
3. Current event is saved to `eventLog`
4. Form re-populates for next type in sequence (Wake → Nap start → Nap end → Bedtime → Wake next day)
5. Modal stays open, focused back on the form
6. After saving Bedtime, date increments by one day and type resets to Wake

### 6. Confirm Before Logging Toggle (CFG-10)

**Location:** Settings modal, "Time & Day" fieldset (renamed from "Day Structure"), last item after "Day cutover hour" and "View grouping".

**Markup in `index.html` fieldset:**
```html
<fieldset>
  <legend>Time & Day</legend>
  <label>Day cutover hour: <input type="number" ... /></label>
  <label>View grouping: <select> ... </select></label>
  <label class="checkboxRow">
    <input type="checkbox" name="confirmBeforeLogging" />
    Confirm before logging
  </label>
</fieldset>
```

**Default state:** `confirmBeforeLogging: false` in `DEFAULT_SETTINGS` in `js/lib/db-shape.js`.

**Behavior:**
- When OFF (unchecked): quick-log buttons log instantly (current v1.0 behavior)
- When ON (checked): quick-log buttons open manual-entry dialog pre-filled with:
  - Current clock time (from `clock.now()`, not `new Date()`)
  - Event type from clicked BUTTON's `.type` field
  - Modal includes Cancel + Save buttons only (NO "Save more")

## Interaction Flows

### Flow 1: Edit History (UI-07)

**Initial state:** History tab opens → "Edit history" button visible → table has no edit/delete/rejected controls visible.

**User clicks "Edit history":**
1. Button label changes to "Done editing"
2. `aria-pressed` becomes `true`
3. Background becomes #eef2ff, text #4f46e5, font-weight 600
4. All `.rowEdit`, `.rowDel`, `.rejected-toggle` become visible in table rows

**User clicks "Done editing":**
1. Button label changes back to "Edit history"
2. `aria-pressed` becomes `false`
3. Button styling reverts
4. All edit/delete/rejected controls hide

**User navigates away from History tab:**
1. History screen unmounts (or is hidden)
2. Next time History tab is selected, screen remounts with fresh state
3. "Edit history" button resets to default (hidden controls)

---

### Flow 2: Confirm Before Logging (LOG-10 + CFG-10)

**Prerequisite:** User enables "Confirm before logging" toggle in Settings.

**When user taps quick-log button:**
1. Button click handler checks `settings.get().confirmBeforeLogging`
2. If true: calls `openManualEntry({ mode: 'add', type: buttonType, time: clock.now(), saveMore: false })`
3. Manual-entry modal opens with:
   - Type field pre-selected (editable, user can change)
   - Time field pre-filled to current time (editable)
   - Cancel + Save buttons only (no "Save more")
4. User adjusts fields or confirms → clicks Save
5. Event logged, modal closes

---

### Flow 3: Save More (LOG-11)

**Prerequisite:** User taps "+ Add event" button (not quick-log confirm flow).

**When modal opens via "+ Add event":**
1. Modal opens with `saveMore: true`
2. "Save more" button is visible
3. User fills in event type, time, date

**User clicks "Save more":**
1. Current event is saved
2. Modal stays open
3. Form re-populates:
   - Type advances: Wake → Nap start → Nap end → Bedtime → (next day) Wake
   - Time field clears (user re-enters)
   - Date: stays same unless type was Bedtime (then increments by 1 day)
4. Focus returns to form
5. User can save more events or click Cancel to close

**After saving Bedtime:**
1. Type resets to Wake
2. Date increments by 1 calendar day (not subjective-night boundary)
3. Form ready for next Wake entry

---

### Flow 4: Collapse/Expand Probability-Band Forecast Card (UI-09)

**When forecast card has probability band (±delta > max_delta):**
1. Card renders in collapsed state by default: `Bedtime • 22:00–23:45 ↓`
2. User taps card
3. Card expands to full card layout (event-label + time-central + prob-list)
4. Chevron changes to ↑ (or › to ↙)

**User taps expanded card:**
1. Card collapses back to single-line format
2. Chevron changes back to ↓

**When new event is logged:**
1. `renderForecastSection()` re-renders all forecast cards
2. Collapsed cards reset to collapsed state (no state persistence)
3. Chevron resets to ↓

## Design Decision Rationale

**From upstream CONTEXT.md (09-CONTEXT.md):**

- **D9-05 (Collapsed card format):** `[Event Label] • [first–last band times] [chevron]` keeps it readable at small size; bullet separator is semantic and familiar.
- **D9-06 (Reset on re-render):** Collapsed state is ephemeral; resetting on re-render avoids complex state management and matches the reactive re-render pattern already in the codebase.
- **D9-07 (Hero never collapses):** Hero card is the primary prediction; collapsing it would reduce prominence. Collapse behavior is limited to the 2×2 forecast grid.
- **D9-08 (No "Save more" in confirm flow):** Confirm-before-logging is a single-event confirmation; "Save more" is for bulk entry via the "+ Add event" button.
- **D9-10/D9-11 (Fixed sequence):** Wake → Nap start → Nap end → Bedtime → (next day) Wake ensures consistency; no algorithm needed.
- **D9-17 (Hero label):** "Next Predicted Event" is explicit and accessible; placed above the time for clear hierarchy.

**From Phase 8 decisions (D8-13):**

- Font weights normalized to 400 and 600 only (no 500, 700).
- All Phase 9 text uses these weights strictly.
