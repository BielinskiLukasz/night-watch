## Interaction Flows

### Flow 1: Switching Algorithm in Settings (TIF-01, D10-11, D10-12)

**Step-by-step:**

1. User opens Settings modal (gear icon)
2. Settings modal populates all fields from `settings.get()`
3. `<select name="forecastAlgorithm">` is set to current value (`'classic'` by default, per D10-13)
4. `openSettings()` checks: if `snap.forecastAlgorithm === 'tif'`, remove `hidden` from `#tifOptions`; else ensure `hidden` is set
5. User scrolls to "Forecast & Prediction" fieldset, sees "TIF Algorithm" sub-section
6. User selects "TIF" from the dropdown
7. `change` event fires on `<select name="forecastAlgorithm">`
8. Event handler: removes `hidden` attribute from `#tifOptions`
9. `trimPct` input and `precisionTarget` input appear — pre-populated from `snap.trimPct` and `snap.precisionTarget`
10. User adjusts trimPct and precisionTarget if desired
11. User clicks Save
12. `settings.update()` fires with new `forecastAlgorithm`, `trimPct`, `precisionTarget`
13. Reactive subscriber chain re-renders Today screen with TIF predictions

**Reverse flow (TIF → Classic):**
- User selects "Classic" from dropdown
- `change` handler: sets `hidden` attribute on `#tifOptions`
- `trimPct` and `precisionTarget` inputs disappear
- On Save: `forecastAlgorithm: 'classic'` is saved; `trimPct`/`precisionTarget` remain in settings at their last values (they are simply unused by the classic algorithm)

---

### Flow 2: Normal TIF Prediction Card Rendering (TIF-09, TIF-10, D10-06)

**Context:** `settings.forecastAlgorithm === 'tif'`, `isLowConfidence === false`.

1. `renderForecastSection()` calls `renderPredictionCard(pred, type, timeFormat)` (or a new TIF-aware wrapper)
2. Card is built as `.prediction-card.tif-card` (no `.collapsed`, no click handler)
3. Append `.event-label` with event type label (e.g., "WAKE")
4. Append `.time-central` with `pred.central` formatted by `formatHHMM()`
5. Append `.time-band` with `formatHHMM(pred.min) – formatHHMM(pred.max)` (displayed window)
6. If `pred.algRange > settings.precisionTarget`: append `.tif-alg-range` with `formatHHMM(pred.algMin)–formatHHMM(pred.algMax)` (original algorithm range, no label prefix)
7. Always append `.tif-score-badge` with `"Precision: " + Math.round(pred.precisionScore) + "%"`

---

### Flow 3: Low-Confidence TIF Card Collapse/Expand (TIF-08, D10-08)

**Context:** `settings.forecastAlgorithm === 'tif'`, `isLowConfidence === true`.

**Default (collapsed):**
1. Card renders as `.prediction-card.probability-band.tif-low-confidence.collapsed`
2. `.card-summary` is visible (CSS: `.prediction-card.collapsed .card-summary { display: flex }`)
3. `.card-summary-label` contains: `"[EVENT_TYPE_LABEL] — Low confidence — [min]–[max]"`
4. `.card-full` is hidden (CSS: `.prediction-card.collapsed .card-full { display: none }`)
5. Chevron shows ↓

**User taps card:**
1. Click handler toggles `.collapsed` off the card
2. `.card-summary` hides
3. `.card-full` becomes visible showing:
   - `.event-label` with event type label
   - `.tif-source-list` with each `sourceWindow` entry as a `<li>` (label left, time range right)
   - `.tif-score-badge` with precision score
4. Chevron changes to ↑

**User taps expanded card:**
1. Click handler toggles `.collapsed` back on
2. Card returns to collapsed state
3. Chevron changes back to ↓

**On re-render (inherit D9-06):** Every `renderForecastSection()` call rebuilds the DOM via `replaceChildren()`. All low-confidence cards reset to collapsed state. No state persistence needed.

---

### Flow 4: Hero Card TIF Badge (D10-07)

**Context:** `settings.forecastAlgorithm === 'tif'`, hero card is rendered.

1. `renderNextEventCard(prediction, timeFormat)` detects TIF prediction (presence of `prediction.precisionScore`)
2. After appending `.time-band`, append a `.tif-score-badge` span with `"Precision: " + Math.round(prediction.precisionScore) + "%"`
3. CSS override `.next-event-hero .tif-score-badge` applies white-on-accent styling automatically

## Design Decision Rationale

**From upstream CONTEXT.md (10-CONTEXT.md):**

- **D10-06 (Normal TIF cards always expanded):** Collapsibility is reserved for low-confidence cards (D10-09). Normal TIF cards carry a precision score that is always informative — hiding it defeats the purpose of displaying confidence. Always-expanded also avoids ambiguity about card state when TIF is active.
- **D10-07 (Hero card badge):** The hero card is the most prominent prediction surface. Adding the precision badge there gives the user an at-a-glance confidence signal for the single most actionable prediction. Even a 100% score is useful — it tells the user TIF is running.
- **D10-08 / D10-09 (Low-confidence reuses Phase 9 mechanism):** Reusing the existing `.card-summary` / `.card-full` / `.collapsed` pattern avoids duplicate collapse logic. Low-confidence cards are conceptually similar to probability-band cards — both represent high-uncertainty predictions that deserve detail on demand but stay compact by default.
- **D10-10 (TIF sub-section inside existing fieldset):** Adding a new top-level fieldset would expand the Settings modal height and displace other controls. A visual sub-section with a separator line keeps the TIF controls clearly grouped without modal bloat.
- **D10-11 (Select pattern for algorithm toggle):** `<select>` is consistent with the existing `statBlend` control in the same fieldset. A toggle button would introduce a new interaction pattern; a dropdown keeps the Settings modal visually uniform.
- **D10-12 (Hidden not disabled for TIF inputs):** Disabling inputs is ambiguous — do they apply or not? Hiding them signals clearly that trimPct and precisionTarget are irrelevant when Classic is selected. The existing `[hidden] { display: none !important }` CSS rule requires no new code.
- **D10-13 (forecastAlgorithm: 'classic' default):** TIF is opt-in. Classic remains the default to avoid surprising existing users. This also means Phase 10 has zero visual impact on anyone who does not explicitly switch to TIF.

**Precision score copy decision:**
"Precision: 92%" over bare "92%" — the label makes the badge self-documenting. On the hero card where other percentage values might appear (not currently, but defensively), the label prevents ambiguity.

**Original range: no label prefix:**
The `.tif-alg-range` element sits immediately below the displayed `.time-band` in the card hierarchy. The visual separation (smaller, more muted) creates sufficient context. Adding "Full range:" or "Algorithm range:" would crowd the compact card. Developers and users who see the subdued line below the displayed window can infer its meaning.

**Source window labels: follow B-21 Step 3 naming:**
The CONTEXT.md discretion note says "follow the naming from BACKLOG.md B-21 Step 3." B-21 uses event-type-qualified names ("Historic wake-up band" not generic "Historic band") which are clearer when multiple event types share similar windows. The copywriting contract above preserves these qualified names.
