<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → header h1 | subjectName flows from settings store to h1 — must use textContent only |
| user → settings modal Save | FormData extracted from form inputs; must pass validateSettings before reaching settings.update() |
| DOM → document.title | Template string assignment; HTML inert in title bar, but must not construct DOM elements from user input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-13 | Tampering | header h1 — subjectName XSS | mitigate | h1.textContent only (never innerHTML); document.title assignment is HTML-inert; maxLen:40 via validator + maxlength="40" attribute (belt-and-suspenders, Pitfall #5) |
| T-2-14 | Tampering | settings modal Save handler | mitigate | validateSettings(raw, {mode:'save'}) called on all 9 fields before settings.update(); validated normalized object (typed values) is what reaches the store — raw FormData strings never persist |
| T-2-15 | Tampering | settings error rendering | mitigate | Error messages rendered via el('p',{textContent:err.message}) — textContent only, never innerHTML (T-07 carry-over from Plan 01-07) |
| T-2-16 | Information Disclosure | stored-but-inert fields (CFG-02..04, 06..07) | accept | Values persist in localStorage but have no behavioral consumer in Phase 2; no PII concern (numeric/boolean settings); Phase 3 will read them |
| T-2-17 | Denial of Service | subjectName length | mitigate | maxlength="40" on input + validator maxLen:40 — settings payload is ~150 bytes total, not a storage exhaustion vector |
| T-2-SC | Tampering | npm/pip/cargo installs | accept | No new packages in this plan — Playwright already installed |
</threat_model>
