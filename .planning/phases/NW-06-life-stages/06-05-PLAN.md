    **Part A — js/ui/settings-modal.js CSV import stages wiring:**

    In the `handleCsvImport` function, change the destructuring of parseCSV's return value from:
    ```js
    const { events, rejectedDays, activityLog, skipped } = parseCSV(csvText);
    ```
    to:
    ```js
    const { events, rejectedDays, activityLog, stages, skipped } = parseCSV(csvText);
    ```

    After the existing `settings.replace(blob)` call (which replaces all settings including the rejectedDays), add:
    ```js
    // Apply auto-detected stages from etap column (D6-07)
    // settings.replace() already reset stages to [] (from DEFAULT_SETTINGS).
    // We now overlay the parsed stages on top. Only apply if stages were found.
    if (stages && stages.length > 0) {
      settings.update({ stages });
    }
    ```

    NOTE: The order matters. `settings.replace(blob)` is called first (with the standard blob built from DEFAULT_SETTINGS + rejectedDays). This resets stages to []. The subsequent `settings.update({ stages })` then injects the parsed stages. This matches the "two-step" pattern used for CSV import: replace first (canonical clean state), then overlay extras.

    Also update the `showStatus` confirmation line to mention stages when any were detected:
    ```js
    if (skipped.length === 0 && (!stages || stages.length === 0)) {
      showStatus(`Import complete — ${dayCount} days loaded.`);
    } else if (skipped.length === 0) {
      showStatus(`Import complete — ${dayCount} days loaded, ${stages.length} stage(s) detected.`);
    } else {
      const rowNums = skipped.map(s => s.row).join(', ');
      const stageNote = stages && stages.length > 0 ? ` ${stages.length} stage(s) detected.` : '';
      showStatus(
        `Import complete — ${dayCount} days loaded.${stageNote} ${skipped.length} row(s) skipped (rows ${rowNums}).`,
      );
    }
    ```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-06-05-02 | Integrity | CSV import replaces stages then re-injects — race if subscribers fire between the two calls | mitigate | settings.replace() then settings.update() are synchronous; the subscriber fires once after settings.update() with the combined state; no visible intermediate state |
| T-06-05-03 | Integrity | CSV import with empty etap column resets existing stages | mitigate | Plan 06-05 only calls settings.update({ stages }) when stages.length > 0; importing a CSV without etap does not overwrite existing stages |
| T-06-05-SC | Tampering | npm supply chain | mitigate | No new runtime dependencies |
