<objective>
Close G-20-15 (20-UAT.md test 15: "cannot see details of next predicted event... include bedtime with/without nap separation") and G-20-16 item 2 (20-UAT.md test 16 root cause #2, .planning/debug/bedtime-nap-same-algo.md): today-screen.js's collapsible "Later today" section explicitly excludes whichever event type is currently shown as the hero, so the next predicted event's own detail card never exists anywhere in the DOM; separately, that same section never substitutes predictions.bedtimeAfterWake for predictions.bedtime once nap is definitively off the table, so the user only ever sees the (possibly stale) blended bedtime value outside the hero slot.

This plan renames the section "Later today" -> "Details", stops excluding the hero's own type, adds the missing bedtimeAfterWake substitution mirroring the hero's own rule, and gives bedtime/bedtimeAfterWake visually distinct labels (forecast.js already computes them as genuinely separate series — see js/lib/forecast.js's bedtimePred vs bedtimeAfterWakePred, Phase 19/21).

Note on tracer-first: this plan deliberately opts out of the tracer-first task shape. today-screen.js's card-rendering architecture (renderPredictionCard / renderTifNormalCard / renderTifLowConfidenceCard, the el()/dom.js helpers, the hero/detail wiring) is already fully proven across Phases 3, 9, 10 and 21 — this is a targeted correction to already-integrated wiring, not a new vertical capability, so an artificial thin-slice-first task would add no information beyond the single coherent edit in Task 1.

Purpose: give the user a real detail view for the event the app is telling them is next, and stop showing an algorithmically-stale bedtime prediction once the day has resolved whether a nap will happen.

Output: today-screen.js's Details section, EVENT_TYPE_LABEL, and the three non-hero card renderers updated; existing E2E/integration assertions that pinned the old (buggy) exclusion behavior corrected to pin the new intended behavior; new coverage proving both gaps are actually closed, not merely relabeled.
</objective>
