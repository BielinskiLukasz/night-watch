<objective>
Close UAT Gap 1 (minor) — button labels and event-list row labels disagree because there are TWO sources of truth in `js/ui/today-screen.js` lines 32-44:

- `BUTTONS` array (lines 32-35): `Woke up`, `Going to sleep`, `Nap start`, `Nap end`
- `EVENT_LABEL` map (lines 39-44): `Wake`, `Bedtime`, `Nap start`, `Nap end`

User clicked "Woke up" expecting that label on the row, saw "Wake" instead. The fix is to collapse the two into one source — `BUTTONS` is the authoritative declaration; `EVENT_LABEL` (if it stays) must derive from it.

**Phase Goal (user story):**

**As a** Nightwatch user logging an event, **I want to** see the same wording on the resulting list row as on the button I clicked, **so that** the app feels coherent and I never second-guess "wait, did 'Wake' come from me clicking 'Woke up' or from something else?".

**Purpose:** This is a single-source-of-truth refactor with regression tests. No new behavior — just removing the divergence the Plan 01-03 header comment already (incorrectly) claims is removed: "BUTTONS config drives all 4 buttons from a single source of truth so the four-type contract has exactly one source of truth." Today that comment is aspirational; this plan makes it literal.

**Source of decisions:** `01-UAT.md` Gap 1 — reported text "yes but event type is not woke up but wake (like logs type in home screen)" + artifact location `js/ui/today-screen.js:32-44`. CLAUDE.md "vanilla-JS PWA, English UI v1" — labels are user-facing strings owned in one place.

**Why depends_on 01-06:** Plan 01-06 modifies the same file (`js/ui/today-screen.js`) — running this plan after 01-06 avoids a merge conflict on the same lines and lets the executor see the cleanest possible diff. If 01-06 is skipped or rejected, this plan can be promoted to wave 1 independently; nothing in the change shape depends on 01-06's content.
</objective>
