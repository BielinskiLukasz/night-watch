<task type="auto">
  <name>Task 2: Enable sticky headers via vertical scroll context (G-NW-11-14)</name>
  <files>style.css</files>
  <action>Add two properties to the `.metricsTableScroll` rule (currently at line 1603): `overflow-y: auto;` to enable vertical scrolling within the container, and `max-height: calc(100vh - 8rem);` to constrain the container height and create the scroll context needed for CSS `position: sticky` to work on `<th>` elements. The `8rem` offset accounts for the top navigation and metrics screen header. This keeps the header row visible when scrolling down through many days of data.</action>
  <verify>
    <automated>grep -A 2 "\.metricsTableScroll {" style.css | grep -c "overflow-y: auto"</automated>
  </verify>
  <done>The `.metricsTableScroll` rule includes both `overflow-y: auto;` and `max-height: calc(100vh - 8rem);`. Running the app and scrolling the metrics table vertically shows the column header row (<th> elements) remain fixed at the top of the scrolling area while data rows scroll beneath.</done>
</task>

<task type="auto">

This allows the metrics table to utilize the wider horizontal space available in landscape mode while maintaining narrower margins. Preserve the portrait values in the default (non-media-query) rules.</action>
