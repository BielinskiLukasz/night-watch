## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings form input → store | confirmBeforeLogging checkbox value from FormData ('on' or null) is coerced to boolean before reaching validateSettings |
| Quick-log → openManualEntry pre-fill | Pre-filled type comes from the BUTTONS static array (D-10 SSOT); clock time from the injected clock adapter (D-07) — no user-controlled string is interpolated |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation |
|-----------|----------|-----------|----------|-------------|------------|
| T-09-04-01 | Tampering | confirmBeforeLogging checkbox | low | mitigate | FormData coercion (=== 'on') maps any non-'on' value to false. validateSettings boolean check further enforces the type constraint before settings.update() is called. |
| T-09-04-02 | Tampering | Pre-fill type from quick-log | low | mitigate | The event type originates from button.getAttribute('data-log'), which maps to the BUTTONS static array — not user-typed input. The openManualEntry validate() function re-validates the type field against the allowed types. |
| T-09-04-03 | Information Disclosure | clock.now() pre-fill | low | accept | The current time is used only to pre-fill the manual-entry form for user editing. No sensitive information is exposed. |
| T-09-04-04 | Tampering | formatLocalISO on clock.now() | low | mitigate | formatLocalISO produces a validated 'YYYY-MM-DDTHH:MM' string. The result is passed as existing.at to openManualEntry where it is further sliced (not innerHTML'd) for the date/hour/minute inputs. |
</threat_model>
