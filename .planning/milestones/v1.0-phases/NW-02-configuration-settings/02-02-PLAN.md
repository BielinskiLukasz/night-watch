<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → settings store | Blob loaded from localStorage may be corrupted, v1, or v3+ |
| settings.update() | Patch from UI Save handler — must be validated before reaching update() (UI's responsibility) |
| cross-store write path | Event-log writes may overwrite settings slice if not mitigated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-05 | Tampering | settings store load path | mitigate | migrateV1ToV2 handles null/v1/v2/v3+; validateSettings mode:'load' applies per-field defaults on invalid data — app always boots |
| T-2-06 | Tampering | cross-store stale-write (intra-process) | mitigate | update() re-reads fresh blob from storage.load() before save to pick up other store's writes (Pitfall #1); tested in cross-store-race.test.js |
| T-2-07 | Tampering | subscriber re-entry | mitigate | Snapshot-then-iterate: const subs=[...subscribers]; prevents Set mutation during iteration (Pitfall #3) |
| T-2-08 | Tampering | cross-tab divergence | accept | Same acknowledged limitation as Phase 1 (single-tab use case); Phase 8 BroadcastChannel is the mitigation path |
| T-2-SC | Tampering | npm/pip/cargo installs | accept | No new packages — node:test built-in, no install step |
</threat_model>
