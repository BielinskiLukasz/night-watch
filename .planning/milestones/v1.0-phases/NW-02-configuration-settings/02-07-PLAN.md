# Phase 2, Plan 07: Gap Closure — Subject Name Default 'Baby' + Header Fallback + Gear Icon Path

**Two render-layer + one default fixes surfaced by Phase 2 UAT Test 1: (a) the header h1 collapses visually on fresh install because subjectName defaults to empty; (b) the inline SVG gear icon is missing most of its outer teeth because the path data was truncated. User chose two-layer fix for (a): set DEFAULT_SETTINGS.subjectName = 'Baby' AND keep a render-layer fallback in header.js to 'Nightwatch' for the case where the user explicitly clears the field.**

## Goals

- **Close UAT Test 1 gap.** Both findings (empty-h1-on-fresh-install, gear-icon-clipped) addressed.
- **Preserve Phase 2 invariants.** BUCKET_CONFIG.defaultCutoverHour stays `4`; no new dependencies; no schema migration; validator unchanged.
- **Phase 2 user story still satisfied.** Cutover-hour set-and-stick flow (UAT Tests 2–5) is untouched; this plan only changes one default + one render-layer fallback + one SVG asset.

## Tasks

### Task 1 — Subject name default 'Baby' + header fallback + modal placeholder

**type:** auto
**files modified:** `js/lib/db-shape.js`, `js/ui/header.js`, `index.html`, `tests/unit/db-shape.test.js`, `tests/e2e/settings-modal.spec.js`

**Action:**

1. **`js/lib/db-shape.js` line 35** — change the default:
   ```javascript
   subjectName:  'Baby',       // CFG-01 default; user can override via Settings modal
   ```
   (was: `subjectName: '',` with comment "empty — header shows nothing until set (CFG-01)")

2. **`js/ui/header.js` line 38** — add render-layer fallback for the explicit-clear case:
   ```javascript
   h1.textContent = snap.subjectName || 'Nightwatch';
   ```
   (was: `h1.textContent = snap.subjectName;`)
   Now h1 and document.title (line 40) both use the same fallback when subjectName is the empty string. Truthy values (including `'<b>test</b>'`) propagate exactly as before — XSS guarantee unchanged.

3. **`index.html` line 132** — add a placeholder hint to the subject name input:
   ```html
   <input type="text" name="subjectName" maxlength="40" placeholder="e.g., Baby, Maya, Liam...">
   ```
   This nudges the user toward overriding the default the first time they open Settings.

4. **`tests/unit/db-shape.test.js` line 24** — update the literal assertion:
   ```javascript
   assert.equal(DEFAULT_SETTINGS.subjectName, 'Baby');
   ```
   (was: `assert.equal(DEFAULT_SETTINGS.subjectName, '');`)

5. **`tests/e2e/settings-modal.spec.js` lines 42 + 47** — update the empty-name spec:
   - Line 42 — update the test name string:
     ```javascript
     test('CFG-01: empty subjectName → h1 + document.title both read "Nightwatch" via fallback (D2-11)', async ({ page }) => {
     ```
   - Line 47 — assert the fallback:
     ```javascript
     await expect(page.locator('header.appHeader h1.subjectName')).toHaveText('Nightwatch');
     ```
   (was: `.toHaveText('')`)

**Acceptance criteria:**

- **Fresh install** (cleared localStorage, first load):
  - Header h1 reads `Baby` (from DEFAULT_SETTINGS).
  - Tab title reads `Nightwatch — Baby` (existing document.title formula picks up the new default).
- **User opens Settings** for first time:
  - Subject name input value is `Baby` (populated from settings.get()).
  - Placeholder text shows `e.g., Baby, Maya, Liam...` (only visible when input is empty — i.e., after user clears it).
- **User overrides to 'Maya' and Saves:**
  - h1 reads `Maya`; tab title `Nightwatch — Maya`.
- **User clears subjectName to empty and Saves:**
  - h1 falls back to `Nightwatch`; tab title `Nightwatch`. (No schema violation; validator allows empty.)
- **XSS spec** (subjectName = `'<b>test</b>'`): h1 reads literal `'<b>test</b>'`, not `'Nightwatch'`. The `||` only kicks in for falsy values; `'<b>test</b>'` is truthy.
- **Test suite:**
  - `npm run test:unit` → 251/251 (one literal updated; integration tests that compare against `DEFAULT_SETTINGS.subjectName` by reference auto-adapt).
  - `npx playwright test` → 40/40 (one spec updated to assert the new fallback).

**Threat surface scan:**

- **T-2-13 (XSS on h1):** Unchanged. Write path is still `textContent`. The `||` operator does not interpret HTML — it just returns the right-hand side if the left is falsy. The literal fallback string `'Nightwatch'` is JS-source-controlled, never user input.
- **T-2-17 (subjectName length):** Unchanged. `maxLen:40` validator + `maxlength="40"` HTML attribute. `'Baby'` is 4 chars, `'Nightwatch'` is 10 — both well under bound.
- **T-2-05 (corrupt-blob recovery):** Unchanged. v1→v2 migration in db-shape.js still injects defaults including the new `subjectName: 'Baby'`. v2 blobs already persisted (e.g., from dogfooding before this fix) keep their stored subjectName — no forced migration of existing user data.
