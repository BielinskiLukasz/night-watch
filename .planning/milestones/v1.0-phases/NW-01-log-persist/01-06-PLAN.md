<objective>
Close UAT Gap 4 (BLOCKER) — extra naps double-render in the event list. Apply the **proper dedupe** (per user direction): every nap renders exactly ONCE in the list; the 3rd+ overflow naps render as faint rows (LOG-09 surfacing preserved) AND keep their `[edit]`/`[×]` affordances (so the user can act on every row they see).

**Phase Goal (user story):**

**As a** Nightwatch user logging more than 2 naps in a day, **I want to** see each nap exactly once in the day list — with a visual cue (faint italic) that I'm over the usual 2-nap budget AND the same `[edit]`/`[×]` controls I have on every other row — **so that** LOG-09's "you logged more naps than usual" surfacing helps me, not confuses me, and **so that** I can manage every event I logged regardless of whether it was the 1st, 2nd, or 5th nap of the day.

**Purpose:** The reported UAT symptom: a 3rd `napStart` event renders TWO rows — one normal `<li>` with `[edit]`/`[×]` (from `day.allEvents`) AND a second faint `<li class="extraNap">` summary row with NO affordances (from `day.extraNaps`). The user sees the same nap twice and can act on only one of the two rows. The fix collapses this into ONE render path:

1. `js/lib/day-bucket.js` continues to detect overflow napStart/napEnd, but now also FLAGS the overflow events with `extra: true` (on a shallow copy — the wire-format on disk is not mutated). The `extraNaps` array stays for any downstream non-rendering consumer (Phase 3+ forecast can still ignore overflow naps).
2. `js/ui/today-screen.js`:
   - `renderDay()` iterates `day.allEvents` ONLY. The second loop over `day.extraNaps` is removed.
   - `renderEventRow(evt)` reads `evt.extra` and conditionally sets the `<li>` className to `'event extraNap'` (both classes — `event` keeps the row picked up by the existing list selectors; `extraNap` triggers the faint italic styling from `style.css`).
   - The `[edit]`/`[×]` affordances are on EVERY row, faint or not.
   - The standalone `renderExtraNapRow` helper is deleted.
3. `style.css` keeps the `.extraNap` rule unchanged — the row that uses it now has children buttons, so check the rule does not hide them.

**Why this approach, not "hide the faint row entirely":** Hiding LOG-09 surfacing would defer a Phase 1 requirement (LOG-09 covers "extra-nap warning"). The user explicitly wants the warning preserved — the issue was the dead-end second row, not the surfacing itself. This plan keeps the surfacing visible AND makes every row actionable.

(a2) include extra naps in allEvents only and let the row renderer style them faint when evt.extra === true." User direction (this session): "I dont want option B, I want to fix that." CLAUDE.md "No `.innerHTML = ` with non-empty data (T-07)" — row rendering continues to use `textContent` via the `el()` helper.
