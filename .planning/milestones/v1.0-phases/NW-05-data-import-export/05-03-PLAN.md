    **Part A — js/lib/import-export.js (new file):**

    Create the module. Import formatLocalISO from './time.js'.

    Export function downloadJSON(storage, clock): reads the current canonical blob via storage.load(), builds the filename as 'nightwatch-' + formatLocalISO(clock.now()).slice(0, 10) + '.json' (per D5-15), serializes via JSON.stringify(blob, null, 2) (per D5-16), creates a Blob object with type 'application/json', creates an object URL, creates a temporary anchor element, sets href and download attributes, appends to document.body, calls .click(), removes from document.body, then calls setTimeout(() => URL.revokeObjectURL(url), 100) (per RESEARCH Pitfall 3 — not immediate revocation). No imports from store modules — receives storage directly.

    **Part B — js/ui/history-screen.js modifications:**

    Extend the mountHistoryScreen function signature to accept an optional onExport callback in deps: { root, eventLog, settings, onExport }. If onExport is provided, render a toolbar div above the table. The toolbar contains a single button with id="exportJsonBtn", type="button", class="btnExport", aria-label="Export sleep data as JSON", textContent="Export JSON". Wire its click event to call onExport(). The toolbar has class="historyToolbar". The toolbar is appended to root before the table; on re-renders (render() is called again by subscriber), the toolbar must persist — use root.querySelector('.historyToolbar') to check if it already exists before creating it again, or structure render() to always prepend a fresh toolbar. Choosing the simpler approach: build toolbar once outside render(), append to root at mount time, then render() only replaces the table portion below it. Adjust root.replaceChildren() call in render() to not clear the toolbar: instead of root.replaceChildren(), clear only the table portion. Use a dedicated tableRoot element that sits inside root alongside the toolbar.

    Implementation structure for mountHistoryScreen:
    1. Clear root and create two children: toolbarEl (if onExport) and tableRootEl
    2. Append both to root
    3. If onExport: build the export button, append to toolbarEl, wire click
    4. render() function replaces only tableRootEl.replaceChildren() (not root.replaceChildren())
    5. All existing build logic (buildTable, renderEmptyState) targets tableRootEl

    This avoids the toolbar being destroyed on every subscriber-triggered re-render.

| Boundary | Description |
|----------|-------------|
| storage.load() → JSON.stringify → Blob | Exported data is user's own localStorage; no external input crosses this boundary on export |
| <a download> → browser file system | Browser handles the download; no server involved |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Information Disclosure | Exported JSON contains full settings including subjectName | accept | Data is user's own, downloaded to their own device. No PII leaves the browser to any third party. |
| T-05-03-02 | Tampering | downloadJSON injects dynamic content into DOM (<a> element) | mitigate | Only href (object URL, no user data) and download (string literal) attributes are set on the anchor; no innerHTML; element is removed immediately after click |
| T-05-03-03 | Availability | URL.createObjectURL not available from file:// in Firefox | accept | Phase 5 app runs from http://localhost dev server; file:// support is Phase 8 concern per RESEARCH §Pattern D |
| T-05-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new runtime dependencies; import-export.js is pure vanilla JS |
</threat_model>
