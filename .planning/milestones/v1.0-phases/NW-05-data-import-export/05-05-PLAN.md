    **Part A — js/ui/settings-modal.js JSON import additions:**

    Inside openSettings (alongside the existing CSV import wiring from Plan 05-04), add JSON import flow:

    1. Wire a one-time click listener on #importJsonBtn: calls document.getElementById('jsonInput').click(). Use the same named-handler + removeEventListener pattern as CSV to prevent listener accumulation on repeated Settings opens.

    2. Wire a 'change' listener on #jsonInput:
       a. Get file = input.files[0]; if (!file) return;
       b. Reset: input.value = '';
       c. Create FileReader.
       d. reader.onerror = () => { showStatus('Could not read file.', true); };
       e. reader.onload = (e) => { handleJsonImport(e.target.result); };
       f. reader.readAsText(file, 'UTF-8');

    3. Implement handleJsonImport(jsonText) as a closure inside openSettings (has access to eventLog, settings, storage):
       a. Parse: let blob; try { blob = JSON.parse(jsonText); } catch { showStatus('Invalid JSON file — could not parse.', true); return; }
       b. Version guard (Claude's Discretion): if (typeof blob.version === 'number' && blob.version > 2) { showStatus('Incompatible file — exported by a newer version of Nightwatch.', true); return; }
       c. Count events for confirmation copy: const eventCount = Array.isArray(blob.events) ? blob.events.length : 0; const dayCount = blob.events ? new Set(blob.events.map(e => e.at && e.at.slice(0,10)).filter(Boolean)).size : 0;
       d. Show confirmation (D5-12): if (!window.confirm('Import ' + dayCount + ' days from JSON? This will replace all current data and settings.')) return;
       e. Call storage.save — but storage is not exposed directly to openSettings in the current signature; confirm it is passed as part of deps (app.js already passes storage per Plan 05-04 Part B). Call storage.save(migrateV1ToV2(blob, DEFAULT_SETTINGS)) first.
       f. Call eventLog.replace(blob).
       g. Call settings.replace(blob).
       h. Show status: 'Import complete — ' + dayCount + ' days restored.'

    Note: migrateV1ToV2 is already imported from db-shape.js (added in Plan 05-04); DEFAULT_SETTINGS is already imported. No new imports needed.

    Note on JSON import vs CSV import ID handling: JSON blobs already have event IDs (from when they were exported). Do NOT call id() on JSON import events — unlike CSV (Pitfall 4 from RESEARCH). JSON events pass through replace() as-is.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-selected JSON file bytes → JSON.parse → replace() | Untrusted file content; must be validated before any state write |
| version field in imported JSON | Controls migration path; must be checked before calling migrateV1ToV2 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05-01 | Tampering | JSON import with crafted event types (non-VALID_TYPES values) | mitigate | eventLog.replace() calls migrateV1ToV2 which preserves events as-is, BUT subsequent addEvent/editEvent calls validate type via VALID_TYPES Set. The events are stored; if an event has an invalid type, it is stored but will not be displayed (day-bucket ignores unknown slot types). Acceptable for Phase 5 — full validation deferred to Phase 8 hardening. |
| T-05-05-02 | Tampering | XSS via JSON settings.subjectName displayed in header | mitigate | Header renders subjectName via textContent (established Phase 2 invariant — T-2-14); no innerHTML path exists for subjectName |
| T-05-05-03 | Tampering | JSON with version > 2 triggers error but user retries with modified blob | accept | User controls their own device/localStorage; there is no server-side enforcement. The version guard prevents accidental corruption from future-version files. |
| T-05-05-04 | Integrity | JSON.parse throws on malformed JSON | mitigate | try/catch around JSON.parse in handleJsonImport; onerror path shows user-visible message; no state is written on parse failure |
| T-05-05-05 | Denial of Service | Extremely large JSON file freezes the browser | accept | JSON.parse of a few hundred KB (years of sleep records) is fast. No reasonable data volume causes a freeze. Phase 8 can add file-size checks. |
| T-05-05-SC | Tampering | npm/pip/cargo installs | mitigate | No new runtime dependencies; all code is vanilla JS |
</threat_model>
