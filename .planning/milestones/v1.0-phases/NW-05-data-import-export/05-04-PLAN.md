<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-selected CSV file bytes → FileReader → parseCSV() | Untrusted file content; user chooses file from filesystem |
| parseCSV() output → store replace() | Parsed events/settings flow into localStorage as canonical state |
| window.confirm() | Synchronous dialog blocks import; user intent confirmed before destructive write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04-01 | Tampering | CSV with crafted event type strings (not wake/bedtime/napStart/napEnd) | mitigate | parseCSV only emits events with type drawn from the fixed column mapping (wake, bedtime, napStart, napEnd); no user-controlled type field in the CSV |
| T-05-04-02 | Tampering | XSS via CSV content in importStatus display | mitigate | showStatus uses statusEl.textContent only (never innerHTML); skipped row reasons are internal enum strings, not raw CSV cell values |
| T-05-04-03 | Integrity | Confirmation dialog bypassed in automated contexts | accept | window.confirm() is synchronous and blocks the call stack; cannot be bypassed without Playwright dialog handler. Playwright tests explicitly handle it with page.once('dialog'). |
| T-05-04-04 | Integrity | Duplicate #csvInput change listeners on repeated Settings opens | mitigate | Use removeEventListener before addEventListener on each Settings open to prevent handler accumulation |
| T-05-04-05 | Integrity | newEventId() called once per imported event; no duplicate IDs | mitigate | id() closure increments a counter per call (Phase 1 implementation); mapping events.map(e => ({...e, id: id()})) calls id() once per event |
| T-05-04-SC | Tampering | npm/pip/cargo installs | mitigate | No new runtime dependencies; all code is vanilla JS |
</threat_model>
